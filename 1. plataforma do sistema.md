# Briefing

O sistema proposto consiste em um SaaS de cardápio digital voltado para estabelecimentos como hamburguerias, pizzarias, esfiharias e restaurantes em geral.

A solução permitirá que clientes, por meio da leitura de um QR Code disponível na mesa, acessem o cardápio de forma anônima, realizem pedidos diretamente para a cozinha e o bar, acompanhem em tempo real os itens consumidos na comanda digital e efetuem o pagamento pelo próprio dispositivo móvel.

Além da experiência do cliente, o sistema também oferecerá suporte operacional interno, permitindo o gerenciamento de pedidos, acompanhamento de produção e análise de dados estratégicos para tomada de decisão.

Os integrantes do time fizeram algumas sujestões (que podem ser alteradas caso não seja a melhor escolha) de um ecossistema formado por:

+ Um banco de dados.
+ Uma API central.
+ Uma ferramenta de visualização de dados como grafana para a gerencia acompanhar os numeros de vendas e etc.
+ Um app PWA para os garçons resgistrarem os pedidos pelo tablet ou smartphone.
+ Um front-end web desktop para a cozinha acompanhar, dar baixa, e talvez imprimir os pedidos.
+ Um front-end web mobile responsivo para os clientes acessarem pelo celular.

## Respondendo a questionamentos 1

O garçom não precisa de um app nativo, pode ser PWA.
Dashbord com grafana foi uma sujestão que veio da necessidade de acompanhar os pedidos em tempo real, preferencialmente em um dashborad com graficos que indicam quais produtos são os mais vendidos, bebidas mais vendidas, ticket médio das mesas e etc. Foi pensada em algumas alternativas como power bi e google loker.
O sistema como um todo precisa trabalhar em tempo real, pois os pedidos precisam chegar na cozinha assim que forem feitos.
Principais funcionalidades na ordem de prioridades são:

1. Visualização do cardápio
2. Fazer pedido (pelo garçom e pelo cliente)
3. Notificação e visualização do pedido pela cozinha.
4. Baixa do pedido pela cozinha ou garçom.
5. Visualização do status pedido pelo cliente.
6. Visualização dos dashboards pela gerencia.
7. Formas de pagamento.

Os primeiros cinco itens da lista precisam estar no mvp inicial para a apresentação para o cliente.

## Respondendo a questionamentos 2

Aceita recomendação de não usar nenhuma ferramenta externa de indicadores de negocio, porem, a visualização dos dados em tempo real é um excelente argumento de venda, precisamos de algo que faça isso.

# Definição da plataforma

O sistema será desenvolvido como uma aplicação **Web com suporte a PWA (Progressive Web App)**, permitindo acesso tanto por dispositivos móveis quanto desktops, sem a necessidade de instalação por meio de lojas de aplicativos.

## Justificativa

A adoção de uma abordagem Web com PWA mostra-se adequada ao contexto do projeto, pois reduz a complexidade de desenvolvimento e manutenção, ao mesmo tempo em que garante ampla acessibilidade. Considerando que o público inclui clientes ocasionais (via QR Code), a ausência de instalação obrigatória torna-se um fator crítico para a adesão ao sistema.

## Perfil do usuário final

O público-alvo da solução é predominantemente composto por usuários jovens, habituados ao uso constante de smartphones e aplicações digitais. Esse perfil apresenta baixa resistência ao uso de tecnologias baseadas em navegador e alta familiaridade com interações via QR Code.

Dessa forma, a utilização de uma aplicação web responsiva acessada diretamente pelo navegador atende às expectativas de usabilidade desse público, eliminando barreiras como instalação prévia de aplicativos e processos de cadastro complexos.

---

## Contexto de uso da solução

O sistema será utilizado em ambientes como hamburguerias, pizzarias e restaurantes, caracterizados por:

+ Interações rápidas
+ Alto fluxo de usuários
+ Necessidade de agilidade no atendimento

Nesse cenário, exigir que o cliente instale um aplicativo comprometeria a experiência e aumentaria a taxa de desistência. A abordagem via navegador, acessada por QR Code, permite entrada imediata no sistema, tornando o processo mais fluido e eficiente.

---

## Acessibilidade e facilidade de uso

A adoção de QR Code como ponto de entrada para o sistema reforça a acessibilidade da solução, permitindo que qualquer dispositivo com câmera e navegador consiga utilizá-la.

Além disso, o uso de PWA possibilita:

+ Interface semelhante a aplicativos nativos
+ Possibilidade de adicionar à tela inicial
+ Experiência contínua sem necessidade de instalação formal

Essa abordagem reduz atrito na interação e melhora significativamente a adesão do usuário.

---

## Custos de desenvolvimento e manutenção

A escolha por uma plataforma web contribui diretamente para a redução de custos, uma vez que:

+ Elimina a necessidade de desenvolvimento separado para Android e iOS
+ Dispensa publicação e manutenção em lojas de aplicativos
+ Permite atualizações centralizadas, sem depender da ação do usuário

Adicionalmente, a aplicação pode ser hospedada inicialmente em provedores gratuitos, o que é compatível com o estágio inicial do projeto e com a necessidade de validação do produto.

---

## Escalabilidade da solução

A arquitetura baseada em aplicação web com API central permite que o sistema evolua de forma gradual conforme a demanda.

Inicialmente, o sistema pode operar em infraestrutura simples (escala vertical). Com o crescimento do número de usuários e estabelecimentos atendidos, torna-se possível migrar para uma abordagem distribuída (escala horizontal), com balanceamento de carga e múltiplas instâncias da aplicação.

Essa flexibilidade garante que a solução não apenas atenda ao cenário atual, mas também suporte sua expansão futura.

---

## Integração com outras tecnologias

A utilização de uma API centralizada favorece a integração com ferramentas externas e novos módulos do sistema.

No futuro, será possível expandir a solução para incluir:

+ Integração com ferramentas de análise de dados
+ Módulos avançados de relatórios
+ Integrações com sistemas de pagamento
+ Conexão com plataformas como Grafana ou outras soluções de BI

Essa capacidade de extensão reforça a longevidade da arquitetura proposta.

---

## Conclusão

Diante dos fatores analisados, a escolha por uma aplicação web com suporte a PWA demonstra-se tecnicamente adequada, economicamente viável e estrategicamente alinhada aos objetivos do projeto. A decisão equilibra experiência do usuário, simplicidade de desenvolvimento e potencial de crescimento, garantindo uma base sólida para a evolução do sistema.
